LE TRAJET SIMPLIFIÉ D’UNE VISITEClique sur les étapes
Point d’entrée

Le navigateur demande une page

GET /spip.php?page=article&id_article=12

Le point d’entrée reçoit la visite. Le runtime Symfony prépare le lancement du noyau HTTP SPIP. Ce schéma résume le chemin documenté, sans détailler chaque classe.

Kernel de démarrage

SPIP prépare les outils communs

Cœur + plugins actifs → conteneur

Le démarrage charge le conteneur compilé ou le recompile si nécessaire. Les services et listeners doivent être prêts avant le traitement de la requête.

Request + noyau HTTP

La requête est représentée par un objet

URL · paramètres · en-têtes

Le noyau HTTP prend en charge la Request. La requête courante est accessible pendant le traitement via RequestStack. Le routage détermine quel contrôleur appeler.

Contrôleur → code SPIP

Le traitement SPIP produit le contenu

Squelettes · formulaires · pipelines

Le contrôleur peut déléguer aux handlers qui exécutent le code historique de SPIP. Le mécanisme de publication reste encore largement présent derrière cette nouvelle entrée.

Response

Une réponse revient au navigateur

Contenu + statut + en-têtes

Le contenu produit peut être capturé puis placé dans une Response. Le cycle HTTP transmet cette réponse au navigateur. Le site continue d’afficher une page SPIP.
